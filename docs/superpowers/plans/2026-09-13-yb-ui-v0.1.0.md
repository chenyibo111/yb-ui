# YB UI v0.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `@yb/tokens`, `@yb/icons`, and `@yb/ui` as a light-theme React component-system foundation with Storybook documentation and consumer-style validation.

**Architecture:** Use a pnpm workspace with independently buildable packages. `@yb/tokens` supplies semantic CSS variables, `@yb/icons` exposes the approved Lucide icon boundary, and `@yb/ui` ships compiled React JavaScript plus compiled CSS. Storybook and a Vite playground consume the workspace packages exactly as future applications will.

**Tech Stack:** React 18.2+ and React 19 compatible peer dependencies, TypeScript, pnpm workspaces, Tailwind CSS v4, CSS variables, Radix UI primitives, Lucide React, React Day Picker, date-fns, tsup, Vitest, React Testing Library, axe-core, Storybook with the Vite framework, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-13-yb-ui-design.md`

## Global Constraints

- Target React only; support React 18.2+ and React 19 through peer dependencies.
- Author UI with Tailwind CSS and semantic CSS variables, but publish compiled CSS so consumer applications do not scan `@yb/ui` source.
- Ship the Cobalt Pulse light theme only; reserve `.dark` token structure without shipping a complete dark theme.
- Use only semantic tokens in components; no hard-coded component colors, radii, shadows, spacing, or typography values.
- Support `zh-CN` and `en-US` through `YBProvider`.
- Use Lucide React through `@yb/icons`, not direct app imports from `lucide-react`.
- Maintain baseline keyboard access, visible focus, label/error associations, ARIA semantics, and AA contrast for primary tokens.
- Keep form rendering primitives independent of React Hook Form and all business logic.
- Keep `Table` presentational and `DatePicker` limited to single-date and date-range selection.
- Every shipped component requires types, Storybook stories, interaction tests, accessibility coverage, and a visual baseline.
